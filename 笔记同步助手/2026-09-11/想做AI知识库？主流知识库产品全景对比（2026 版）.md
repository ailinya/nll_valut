## 一、个人 PKM 赛道

### 1.1 产品定位

| 产品 | 定位一句话 | 开源 / 协议 | GitHub Stars（约） |
| --- | --- | --- | --- |
| Obsidian | 本地 Markdown + 双向链接 + 插件生态，唯一「给人用」的标杆 | 免费个人 / 商业授权，核心闭源 | — |
| Logseq | 开源大纲式双链笔记，开发者 & 隐私派首选 | AGPL-3.0 | 高 |
| Roam Research | 每日笔记 + 双向链接图谱鼻祖，学者/深度写作者 | 商业 SaaS | — |

### 1.2 功能矩阵（赛道内对比）

| 能力 | Obsidian | Logseq | Roam Research | 思源笔记 |
| --- | --- | --- | --- | --- |
| 数据存储 | 纯本地 Markdown | 纯本地（Markdown/EDN） | 云端 | 本地 + 可选云 |
| 双向链接 / 图谱 | ✅ 极强 | ✅ | ✅ 开创者 | ✅ |
| 大纲 / 块引用 | 插件增强 | ✅ 原生大纲 | ✅ 原生 | ✅ 块级 |
| PDF 标注 | 插件 | ✅ | 弱 | ✅ |
| 插件生态 | ⭐⭐⭐⭐⭐ 最繁荣 | 中 | 弱 | 中 |
| 协作 | 弱（靠第三方） | 弱 | ✅ 原生 | ✅ |
| 上手难度 | 中（需折腾） | 中 | 高（学习曲线陡） | 低-中 |

### 1.3 优劣与复杂度

-   Obsidian：生态最繁荣、自由度最高；缺点是核心闭源、协作弱、需手动配插件链 → 复杂度中
    
-   Logseq：真正开源 + 本地优先 + 大纲思维，适合开发者；缺点是 UI/生态略逊 Obsidian → 复杂度中
    
-   Roam Research：理念领先、适合深度思考；缺点是按年订阅贵、闭源、协作一般 → 复杂度高
    
-   思源笔记：块编辑体验好、中文友好、兼顾本地与云；社区规模较小 → 复杂度低-中
    

> 赛道结论：隐私 & 生态选 Obsidian/Logseq；深度写作思维选 Roam；中文块笔记选思源。 这一赛道与 AI 记忆层（③）本质不同——PKM 是「人读」的，记忆层是「AI 读」的。

## 二、团队协作 & 企业知识库赛道

### 2.1 代表选手

| 产品 | 阵营 | 典型场景 | 私有化/合规 |
| --- | --- | --- | --- |
| Notion | 海外 | 块编辑 + 数据库 + Wiki 一体化，个人与小团队 All-in-One | 弱（SaaS 为主） |
| Confluence | Atlassian | 中大型研发团队标配，深度绑定 Jira | 支持 Data Center |
| 飞书知识库 | 字节 | 国内企业首选，打通 IM/日历/审批 | 支持 |
| 语雀 | 阿里 | 国内技术团队知识仓库 | 支持 |
| SharePoint | Microsoft 365 | 大型企业/政企集团门户 | ✅ 强（私有化） |
| 腾讯乐享 / ima | 腾讯 | AI 知识库 + 学习平台 / 微信生态剪藏 | 支持 |
| 蓝凌 aiKM、ONES Wiki、PingCode | 国产 | 大型组织/研发套件级 KM | ✅ 私有化 |

这一赛道主流产品超过 20 款，上面是 2026 年仍有高声量的代表。选型核心是「是否与现有办公生态绑定」——用飞书选飞书、用 M365 选 SharePoint、用 Atlassian 选 Confluence，强行跨生态代价很大。

### 2.2 与 AI 原生知识库的边界

传统协作文档的「知识库」多为人工结构化 Wiki，AI 检索能力弱；而 ③④⑤ 赛道的产品天然以 RAG / 图谱 / Agent 为核心。二者正在融合（如 Notion AI、飞书智能伙伴、ima、腾讯乐享 AI），但底层范式仍是「文档协作」vs「检索/推理引擎」。

## 三、AI 记忆层赛道（③）—— 与 Zep 正面竞争

这是上一轮对比中最值得补充的一条线。Zep 只是「记忆层三巨头」之一，另两位是 Mem0 和 Letta；LangMem 则是 LangChain 生态的原生方案。

### 3.1 产品定位

| 产品 | 一句话定位 | 开源 / 协议 | Stars（约，2026-09） |
| --- | --- | --- | --- |
| Zep | 时序上下文图谱，专治「事实随时间变化」 | 商业 + 开源层 | — |
| Mem0 | 通用记忆层，接入最快，框架无关 | Apache-2.0 | 64K+ \[citation:28\]\[citation:32\] |
| Letta（原 MemGPT） | Agent 自主管理记忆块，把记忆做成「类操作系统」 | Apache-2.0 | 23K+ \[citation:33\] |
| LangMem | LangChain/LangGraph 原生记忆 SDK | 开源（LangChain 生态） | — \[citation:2\]\[citation:10\] |

### 3.2 功能矩阵（赛道内硬碰硬）

| 能力 | Zep | Mem0 | Letta | LangMem |
| --- | --- | --- | --- | --- |
| 多层记忆 | 时序图谱 | 用户/会话/Agent 三级 | 核心/回忆/归档三级 | 语义/情景/程序三类 |
| 时序推理（事实带有效期） | ✅ 最强 | 部分 | ❌ | ❌ |
| Agent 自主读写记忆 | 有限 | 提取/更新 | ✅ Agent 自编辑 | ✅（含程序记忆） |
| 冲突处理 | ✅ 图谱合并 | ✅ 自动 | 自编辑 | 后台 Manager |
| 合规（SOC2/HIPAA） | ✅ 最强 | SOC2/HIPAA/BYOK | — | 取决于部署 |
| 框架绑定 | 中等 | 框架无关 | 内存耦合其运行时 | 强绑 LangGraph |
| 托管服务 | ✅ | ✅ | ✅ Cloud | ✅ 托管 |
| 自托管 | 部分 | ✅ | ✅ Docker | ✅ |

### 3.3 各自不可替代的差异化

-   Zep：时序推理 + 企业合规双王牌。用户从 Adidas 换到 Nike，能正确处理「事实随时间变化」；SOC2/HIPAA 适合医疗/金融 \[citation:14\]
    
-   Mem0：接入速度最快——三行代码、框架无关、多信号检索（语义+BM25+实体），托管 + 自托管两种用法 \[citation:24\]\[citation:36\]
    
-   Letta：Agent 自主权最大——自编辑记忆块、Sleep-Time Compute 离线整理、ADE 可视化调试；代价是学习曲线陡、内存自编辑破坏 prompt 缓存、Token 开销更高 \[citation:25\]\[citation:29\]
    
-   LangMem：唯一能让 Agent 改写自身系统提示（程序记忆）；与 LangGraph 深度集成，强绑 LangChain 生态；注意：第三方基准 p95 延迟 59.82s，亚秒级召回应改用 Mem0（0.2s）或 Zep \[citation:14\]
    

选型红线：交互式 Agent 要求低延迟 → 避开 LangMem，选 Mem0/Zep；要 Agent 自主进化行为 → Letta/LangMem；要合规 + 时序事实 → Zep。

## 四、企业 RAG 框架赛道（④）—— WeKnora 与 Yuxi 所在战场

### 4.1 产品定位

| 产品 | 一句话定位 | 开源 / 协议 | Stars（约） |
| --- | --- | --- | --- |
| WeKnora | 腾讯开源 MIT，三模式一体，上手最快 | MIT | — |
| Yuxi（语析） | 全栈智能体平台，知识库+图谱+Agent+沙盒，一体化最高 | MIT（开源） | — |
| Dify | 可视化 LLMOps + Agent 编排，生态最广 | Apache-2.0 衍生 | 154K+ \[citation:26\]\[citation:30\] |
| RAGFlow | 专注文档问答，PDF/表格解析最强 | Apache-2.0 | 高 |
| QAnything | 网易有道，自研 RAG，跨语言 + 全离线 | AGPL-3.0 \[citation:11\] | 中 |

### 4.2 功能矩阵

| 能力 | WeKnora | Yuxi | Dify | RAGFlow | QAnything |
| --- | --- | --- | --- | --- | --- |
| 知识库 RAG | ✅ | ✅ | ✅ | ✅ | ✅ |
| 知识图谱 | ✅ | ✅ | 插件 | 元数据过滤 | ✅（图检索） |
| 可视化工作流 | 中 | ✅ | ✅ 强 | ✅ 画布 | 弱 |
| Agent 编排 | 中 | ✅ 沙盒隔离 | ✅ 强 | ✅（v0.20+）\[citation:27\] | ❌ |
| 文档解析 | 中 | 中 | 中 | ✅ DeepDoc 最强 | ✅ 强（中文优化） |
| 混合检索 + Rerank | ✅ | ✅ | ✅ | ✅ 三路并行 | ✅ 两阶段 |
| 代码执行沙盒 | ❌ | ✅ 独有 | 插件 | ✅（v0.25 Agent 沙盒）\[citation:35\] | ❌ |
| 私有化 | ✅ MIT | ✅ MIT | ✅ | ✅ | ✅ 全离线 |
| 上手难度 | ⭐ 最低 | ⭐⭐⭐ 高 | ⭐⭐ 低-中 | ⭐⭐ 中 | ⭐⭐ 中 |

### 4.3 关键差异化能力

-   WeKnora：上手最快（MIT 协议商用无忧），三模式一体，适合快速把「文档变问答」 \[citation:26\]
    
-   Yuxi：沙盒隔离文件系统——Agent 文件操作安全可控 + artifacts 产物交付，是五者中独有的；一体化程度最高但运维最重 \[citation:35\]
    
-   Dify：生态与社区最广（154K Stars、Apache-2.0、Marketplace 插件市场、SOC2 Type II + ISO 27001 企业版）；可视化编排 + 知识流水线 + 可观测性，适合「从原型到生产不重构」 \[citation:26\]\[citation:30\]
    
-   RAGFlow：文档解析之王——DeepDoc 用 OCR + TSR + DLR 三视觉模型，表格/多栏/图表保留结构；0.23+ 引入父子分块、图/表上下文窗口；0.25 加入 Agent 沙盒、用户级记忆隔离、发布灰度 \[citation:27\]\[citation:31\]\[citation:35\]
    
-   QAnything：跨语言 + 全离线（拔网线可用、纯 CPU、默认 ≥20GB RAM）；BCEmbedding 双语跨语言 SOTA；⚠️ AGPL-3.0 强 Copyleft，闭源商用需谨慎 \[citation:11\]\[citation:15\]
    

WeKnora vs Yuxi 高度重叠（都是国产 MIT 开源、RAG+图谱+私有化），更接近「二选一」；Dify 与 RAGFlow 则是「编排广度 vs 解析深度」的取舍；QAnything 因协议限制更适合内部/开源场景。

-   局限：专注代码库场景，非通用文档 RAG \[citation:9\]

## 七、选型决策框架

### 7.1 先回答「你在哪条赛道」

```
问题 A：是「人」要记住知识，还是「AI」要记住/检索知识？
├─ 人 → 赛道 ①（Obsidian / Logseq / Roam / 思源）
└─ AI → 继续判断：

问题 B：AI 需要「跨会话记住用户/事实」（有状态 Agent）？
├─ 是 → 赛道 ③
│   ├─ 要时序推理 + 合规（医疗/金融）      → Zep
│   ├─ 要最快接入、框架无关                → Mem0
│   ├─ 要 Agent 自主进化 + 可视化调试      → Letta
│   └─ 已在 LangChain/LangGraph 生态       → LangMem
│
└─ 否（把「文档」变成「问答/检索/推理」）→ 赛道 ④⑤
├─ 快速搭建、上手优先                  → WeKnora
├─ 可视化编排 + 生态插件               → Dify
├─ 复杂文档（PDF/表格/多栏）解析为王   → RAGFlow
├─ Agent 要动手产文件（沙盒）          → Yuxi
├─ 跨语言 + 全离线 + 闭源需谨慎协议    → QAnything
└─ 代码库理解 / 省 Token               → Graphify
```

### 7.2 高频组合方案

| 你的场景 | 推荐组合 |
| --- | --- |
| 个人第二大脑 + 本地优先 | Obsidian / Logseq |
| 企业团队 Wiki + AI 问答 | 飞书知识库/Confluence + Dify/RAGFlow |
| 有状态 AI 客服/助手 | 赛道 ③：Mem0（通用）/ Zep（合规时序） |
| 文档问答 POC，越快越好 | WeKnora 或 Dify |
| 复杂 PDF/合同/报告 RAG | RAGFlow（解析强） |
| Agent 动手干活 + 产出文件 | Yuxi |
| 代码库 AI 辅助 + 省 Token | Graphify |
| 国产大模型 + 私有化 + MIT | WeKnora / Yuxi（二选一） |

## 八、关键风险提示

1.  许可协议：QAnything（AGPL-3.0）、Logseq/思源（AGPL-3.0）属强 Copyleft，闭源商用需法务评估；WeKnora/Yuxi（MIT）、Mem0/Letta/Dify/RAGFlow/Graphify（Apache-2.0/MIT）商用友好 \[citation:11\]\[citation:13\]
    
2.  赛道错配：把 RAG 框架当 PKM 用、把记忆层当文档问答用，都会事倍功半——先定位赛道再选型
    
3.  动态指标：Stars / 版本 / 定价变化快，以官方仓库为准（本报告数据 2026-09）
    
4.  深度验证建议：WeKnora vs Yuxi、Mem0 vs Zep vs Letta 这类「赛道内二选一」，最佳做法是同数据集跑 POC + 评测 RAG 准确率/延迟/Token 成本

## 九、结论

-   赛道 ①：Obsidian 生态最强，Logseq 开源替代最优
    
-   赛道 ③ 记忆层：`Mem0`（快）vs `Zep`（时序+合规）vs `Letta`（自主）vs `LangMem`（LangChain 生态）——四选一看技术栈与延迟要求
    
-   赛道 ④ RAG：`WeKnora ≈ Yuxi`（国产 MIT，二选一）、`Dify`（广度）、`RAGFlow`（解析深度）、`QAnything`（离线跨语言，注意协议）
    
-   赛道 ⑤ 代码图谱：Graphify 独树一帜，Token 效率惊人
    

一句话选型：人的知识 → PKM；AI 的记忆 → 记忆层；AI 读文档 → RAG；AI 懂代码 → 图谱。
